# 前端开发常用规则与注意事项（建议每次按需翻一眼）

本文件默认针对子项目 **`web/yes-one-api`**（Vue 3 + Vite + Element Plus + UnoCSS + Pinia，路径别名 `@` → `src`）。

## 组件与状态管理

- **优先复用现有实现**：新增功能先在 `web/yes-one-api/src/components/`、`views/` 中查找类似页面或布局（如 `Layout.vue`），避免重复造轮子。
- **全局状态**：跨路由共享状态放在 `web/yes-one-api/src/store/modules/**`（Pinia），入口为 `store/index.ts`（`setupStore`）；不要在各处重复读写 `localStorage`。业务侧统一 `import { … } from "@/store"`；与认证、系统配置相关的逻辑对齐现有 `store/modules/user.ts`、`store/modules/system.ts`。
- **最小状态原则**：只在一个地方存“真状态”，其他地方用 `props` / `computed` 推导，减少重复字段。
- **禁止随意跨层访问**：优先使用 `props / emits`、`provide/inject`，不要直接改全局单例或挂载到 `window`。
- **命名清晰**：组件名、`ref` 名、`emit` 事件名直观表达作用，例如：`videoLoading`、`update-current-time`。

## 接口与数据处理

- **接口路径不可猜测**：只能依据接口文档或现有 `web/**/src/api/*.ts`，禁止凭感觉“补一个接口”。
- **统一使用项目封装的请求工具**：在本仓库中，Vue 前端优先通过 `web/yes-one-api/src/api/request.ts` 暴露的 `request` 实例调用接口，不要直接裸用 `fetch/axios`。`baseURL` 由环境变量 `VITE_API_BASE_URL` 与本地代理约定（见 `vite.config.ts`），不要随意改默认超时等行为，除非有明确需求。
- **数据转换集中处理**：接口回来的字段统一在一处做 `toCamelCaseObject`、`dayjs` 格式化，再传给组件。
- **处理并发与竞态**：列表加载、快速切换筛选条件等异步流程，尽量使用「请求序号 / AbortController + 仅最新请求生效」模式，避免旧请求覆盖新数据。

## 表单与校验

- **所有可编辑字段都应纳入表单模型**（如 `formInfo`），不要在模板里凭空用局部变量承载重要数据。
- **校验规则显式写在表单配置中**，避免散落在 `watch` 或业务逻辑里。
- **涉及上传/异步变更的字段**，在成功后显式调用 `validateField`，保持界面校验状态同步。
- **默认值谨慎处理**：仅在确有业务含义时设置非空默认值，否则保持为空，避免误导用户。

## 样式与布局

- **沿用现有方案**：优先使用 UnoCSS / 项目现有 `class` 风格，不随意夹杂新命名体系。
- **组件内部样式尽量使用 `scoped` 或局部样式**，避免无前缀的全局选择器。
- **时间、数字等表格列的宽度和对齐方式保持一致**（例如时间列统一 `width="110" align="center"`）。
- **避免魔法数**：常用间距、字号尽量使用现有工具类（如 `py-4`、`text-sm`）。

## 国际化与文案

- **用户可见文案**：优先使用 `web/yes-one-api/src/i18n` 中的 `translate`（或既有 i18n 写法），与现有页面保持一致；避免在业务代码中硬编码大量中文碎片而不走同一套机制。

## 可读性与维护

- **小函数拆分**：超过 50 行或包含多重嵌套的逻辑，优先拆分为多个小函数。
- **注释写“为什么”，不是“做了什么”**：只在意图不明显、或有重要业务约束时写注释。
- **日志输出适度**：调试时可以 `console.log`，提交前应去掉或收敛到统一的调试工具。

## 性能与交互体验

- **高频交互加防抖/节流**：搜索输入、时间轴拖动、滚动监听等易产生大量事件的操作，应使用 `debounce/throttle`。
- **避免重复请求**：同一数据在短时间内重复使用时，考虑缓存或请求合并。
- **加载状态明确**：涉及接口调用的按钮/时间轴，需配套加载态（如 `loading`、禁点、光标反馈）。

## 安全与健壮性

- **所有接口返回都做类型与空值保护**：对齐现有写法，对 `ApiResponse<T>` 先判断 `success`，对 `data` 使用 `Array.isArray`、可选链、`??` 默认值等，避免直接解构空值；类型定义放在 `web/yes-one-api/src/types/**` 并与 `api` 模块一致。
- **链接与文件地址使用安全处理**：对用户可见的外链避免直接拼接不可信 URL；需要跳转时使用 `vue-router` 或经校验的地址。
- **涉及额度、充值、计费、配额等字段时**，改动前务必再次确认业务含义与单位（与后端约定一致）。
