# 核心规则（必读）

## 目标

在保证正确性的前提下，以最小改动完成任务，并保留可复盘记录。

## 必须遵守

1. 沿用现有代码风格与目录结构，避免无关重构。
2. 任务不清晰时先确认，不带假设直接改代码。
3. 接口路径仅在有明确文档或明确指令时调整。
4. 先说明改动范围（1-3 条），再实施修改。
5. 修改前端子项目 `web/yes-one-api/` 后执行必要校验：在该目录下运行 **`pnpm lint`**；涉及类型或较大 TS 改动时补充 **`pnpm type-check`**（脚本见该目录 `package.json`）。
6. 输出结果必须包含：已完成项、未完成项、风险点、验证建议；与 `templates/task-log.md` 对齐。若存在需跟进或人工接手的事项，另列「接下来要做的事」，若无则写「无」或省略该小节。

## 禁止事项

- 未经指令改动无关目录与命名体系。
- 未经确认批量改接口路径或关键业务流程。
- 跳过校验直接宣称完成。

## 上下文策略

路径均以**仓库根目录**为基准（避免相对 `rules/` 的歧义）。

- 执行顺序：先读 `ai-agent/INDEX.md`，再读本文件与 `ai-agent/goals/now.md`。
- 必读：本文件 + `ai-agent/goals/now.md`
- 按需：`ai-agent/templates/` 与 `ai-agent/logs/`
- 不要求每次通读整个 `ai-agent/` 目录
